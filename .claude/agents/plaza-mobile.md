# plaza-mobile — 광장 모바일 대응

## 먼저 읽을 것

`BRIEF.md` 9절, `CONTRACT.md` 2절.

## 왜 이 작업이 필요한가

링크 페이지는 "직접 해볼 수 있어요"라고 기대치를 올려놓고 광장으로 보낸다.
그런데 아이들이 만든 게임 중 상당수가 방향키·스페이스바를 쓴다. 모바일엔 키보드가 없다.

**눌렀는데 화면만 뜨고 조작이 안 되면 최악의 경험이다.**
기대를 잔뜩 올려놓고 배신하는 셈이라, 아무것도 없는 것보다 나쁘다.

링크 페이지를 아무리 잘 만들어도 도착지가 부서져 있으면 전부 무의미해진다.

## 소유 파일

```
광장 작품 상세 화면
광장 작품 업로드 화면
작품 데이터 스키마
```

`/link/**`(A), `/api/plaza/**`·썸네일(B)은 건드리지 않는다.

---

## 작업 1 — PC 전용 안내 배너 (최우선)

모바일 접속 + PC 전용 작품이면 작품 상세에 안내를 띄운다.

- 문구: **"이 작품은 PC에서 해보세요"** 수준으로 간결하게
- 사과하거나 모호하게 쓰지 않는다. 무엇이 안 되고 어떻게 하면 되는지만
- 작품 자체는 계속 보이게 둔다. 접근을 막지 않는다

**이 작업만으로 최악의 경우를 막을 수 있다.** 작업 2가 늦어져도 이건 먼저 끝낸다.
링크 페이지를 건드리지 않고도 효과가 있고, 광장 자체에도 도움이 되는 개선이다.

## 작업 2 — 모바일 지원 플래그

작품 업로드 시 "모바일에서도 되나요" 체크박스 추가.

- 필드명은 `CONTRACT.md` 2절의 **`mobileSupported`** (bool). 임의로 바꾸지 않는다
- 기존 작품의 기본값을 어떻게 할지 결정해 보고한다
  (전부 false로 두면 링크 페이지에 아무것도 안 뜨고, 전부 true면 부정확하다.
  카테고리별 일괄 지정 등 현실적인 안을 제안할 것)
- 이 필드를 작업 1의 배너 조건으로도 쓴다

**필드가 준비되면 B에게 알린다.** B가 필터링을 켤 수 있다.

## 참고 — 이미 있어서 만들지 않아도 되는 것

광장을 확인한 결과 아래는 이미 존재한다. 새로 만들지 말 것.

- 체험하기 기능
- 카테고리(웹/앱/게임/코드)·학년 배지
- 비로그인 열람·체험
- 모바일 레이아웃

---

## 하지 말 것

- 링크 페이지 코드 수정
- 썸네일 파이프라인 수정 (B 소유)
- 광장 전면 리디자인 — 이번 작업 범위가 아니다
- `mobileSupported` 필드명 변경

---

## 완료 조건

- [ ] 모바일에서 PC 전용 작품을 열면 안내가 뜬다
- [ ] 모바일 지원 작품에는 안내가 뜨지 않는다
- [ ] 데스크톱에서는 안내가 뜨지 않는다
- [ ] 업로드 화면에 체크박스가 있고 저장된다
- [ ] `mobileSupported` 필드명이 CONTRACT와 일치한다
- [ ] 기존 작품 기본값 처리 방안을 보고했다
- [ ] B에게 필드 준비 완료를 알렸다
