# link-review — 검수

## 먼저 읽을 것

`BRIEF.md` 전체. 특히 **1절(역할)과 2절(금지)**.

## 목표

구현 결과가 기획 의도대로 나왔는지 확인하고 리포트를 낸다.
코드를 고치지 않는다. 문제를 발견하면 해당 에이전트에게 넘긴다.

## 검수 관점

동작 여부보다 **의도가 지켜졌는지**를 본다.
"에러 없이 잘 돈다"는 이 페이지의 성공 기준이 아니다.

---

## 1. 의도 검수 — 가장 중요

- [ ] 광장 카드가 화면에서 **가장 눈에 띄는 요소**인가
      (문의 버튼이나 학원 페이지 버튼이 더 강하면 실패다)
- [ ] 첫 화면에서 스크롤 없이 **판별 줄 + 헤드라인 + 광장 카드 일부**가 보이는가
- [ ] 헤드라인 카피가 원문 그대로인가 — "더 자연스럽게" 수정되지 않았는가
- [ ] 학원 자랑 문구("창의력", "자기주도" 등)가 슬며시 추가되지 않았는가
- [ ] `BRIEF.md` 2절 금지 섹션이 하나도 없는가
- [ ] 전체 스크롤이 두 화면을 넘지 않는가
- [ ] 문의 3종의 위계가 살아 있는가 (예약 > 카톡·전화)
- [ ] 전화 옆에 운영시간이 표기되어 있는가

## 2. 실기기 확인

**시뮬레이터가 아니라 실제 기기 + 실제 인스타 인앱 브라우저.**
인앱 브라우저는 일반 사파리/크롬과 동작이 다르다. iOS와 안드로이드도 서로 다르다.

- [ ] iOS 인스타 인앱 브라우저에서 하단 버튼이 잘리지 않는가
- [ ] 안드로이드 인스타 인앱 브라우저에서도 동일한가
- [ ] 첫 화면이 3초 안에 뜨는가 (LTE 기준)
- [ ] `tel:` 링크가 실제로 걸리는가
- [ ] 카톡 링크가 인앱 브라우저에서 앱으로 넘어가는가
- [ ] 지도 링크가 지도 앱으로 넘어가는가

## 3. 연결 흐름

링크 페이지 단독이 아니라 **인스타 → 링크 → 광장 → 체험**까지 이어서 확인한다.

- [ ] 광장으로 넘어갔을 때 모바일에서 정상적으로 보이는가
- [ ] 미리보기에 뜬 작품을 실제로 눌러서 체험이 되는가
- [ ] PC 전용 작품을 모바일에서 열면 안내가 뜨는가
- [ ] 로그인 요구 없이 여기까지 되는가
- [ ] 세 화면(인스타 / 링크 / 광장)의 톤이 일관된가

## 4. 장애 상황

- [ ] API를 강제로 실패시켰을 때 **광장 버튼이 그대로 살아 있는가**
- [ ] 빈 배열이 왔을 때 레이아웃이 깨지지 않는가
- [ ] 썸네일 하나가 404일 때 깨진 이미지가 노출되지 않는가
- [ ] 아주 긴 제목의 작품이 레이아웃을 밀지 않는가

## 5. 마감 상태

- [ ] `TODO_` 상수가 전부 실제 값으로 채워졌는가
- [ ] 그럴듯한 가짜 값이 들어가 있지 않은가 (전화번호·주소를 특히 확인)
- [ ] 아웃바운드 링크에 `from`/`target` 파라미터가 붙어 있는가
- [ ] 오픈그래프 이미지가 실제로 뜨는가 (카톡으로 링크를 보내 확인)
- [ ] 키보드 포커스가 보이는가
- [ ] `prefers-reduced-motion`에서 모션이 멈추는가

---

## 리포트 형식

```
## 통과
- (항목)

## 수정 필요
- [담당 에이전트] 문제 / 재현 방법 / 기대 동작

## 판단 필요 (사람에게)
- (기획 의도와 관련해 사람이 결정해야 하는 것)
```

**의도 검수(1절) 실패는 심각도를 높게 잡는다.**
버그는 고치면 되지만, 광장이 주인공이 아니게 되면 페이지 전체가 목적을 잃는다.
